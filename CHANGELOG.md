# Changelog

## Unreleased

### Refactors

- **One runner source, verified.** `ext_runner` existed in three forms: the real module, a stale copy embedded in `run_coreframe.pyw` (missing the `orjson` JSON shim, with mojibake in its comments) and the runner build. The embedded copy is now generated byte-for-byte from `coreframe/extensions/ext_runner.py` by `tools/sync_ext_runner_source.py`, and CI fails on drift.
- **Dead code removed:** `ExtensionSecurity` (428 lines, zero callers; the live guarantees are the consent guards and path validation that remain), `bridge.set_busy`, `bridge._find_system_python`, `loader.load_deferred` and its now-unused state, `static/loading.html` (no references), and the `/api/extensions/<id>/load` handler no longer pretends to load a deferred extension - it reports the load error instead.
- **One extension payload builder:** `/api/extensions` assembled the same dict three times (loaded, denied, pending). Now a single `_ext_payload` helper.
- **The API routes are a package.** `coreframe/routes/api.py` became `coreframe/routes/api/` with `status`, `actions`, `permissions`, `lifecycle`, `serving` and `debug` — one concern per module, same public routes.
- **`coreframe/__init__.py` is lazy (PEP 562).** Importing a leaf module such as `coreframe.config` used to drag in Flask and cost 4.9 s; it is 275 ms now, and `DATA_DIR` ended up with exactly one source instead of two that could disagree.
- **The launcher's early boot and diagnostics moved to `coreframe/host/`.** Bound under their original names, so every `_trace` call site is unchanged. The window-management core stays in `run_coreframe.pyw` because its functions share live state through module globals (pitfall 41).

### Features

- **The renderer sleeps while the window is minimized.** `window.minimize()` only changed `WindowState`, so WebView2 kept the whole renderer resident (212 MB private of a 412 MB tree on a fresh boot). The host now hides the controller and calls `TrySuspendAsync()` on minimize, and `Resume()` on restore; the controller is reached through the wrapper's private `_coreWebView2Controller` field because pywebview exposes neither it nor suspend. Measured on the frozen exe: renderer 212 → 93 MB and tree 412 → 248 MB while minimized, 113/360 MB after restore. A 65 s suspend drops the socket (`/api/health` clients 1 → 0) and the client reconnects on resume; extensions never stop. Taskbar restore and tray open both wake it (pitfall 52).
- **A restored window no longer comes back blank.** The wake was bound to `restored`, but this app runs maximized and a taskbar restore raises `maximized` instead, so the controller stayed hidden and the content only appeared after clicking the title bar's maximize/restore button. The wake now listens to both events (pitfall 52).
- **`/api/window/focus` wakes the window from Python.** A suspended renderer runs no JS, so the `focus_window` socket relay could not answer it - and that route is also the second-instance handshake, so launching CoreFrame again while minimized did nothing. The host registers `_focus_callback` on `coreframe.app`, the same pattern as `_shutdown_callback`, and the route calls it before emitting the socket event.
- **The widget context menu names the build it belongs to.** The header showed the extension name and its permission level but not the version, which is the only thing that tells two installed builds apart. It now renders `Name  v1.1  [LEVEL]`; a long name ellipsises instead of pushing the version out.
- **`keep_alive` reaches the frontend.** The manifest flag documented in `AGENTS.md` was never emitted by the API, so the opt-out could not actually take effect.
- **`serve_data` and `keep_alive` are documented** in `docs/EXTENSIONS.md`, along with the `/ext-data/<id>/<path>` route.

### Performance

- **An extension's CSS and JS load when its card is near the viewport, not at boot.** Loading every stylesheet up front was the most expensive thing the page did at scale: measured in headless Chromium, 1.000 sheets cost 412 ms and 3.000 cost 8.1 s, and the curve is superlinear. `static/js/app/03-assets.js` now watches cards with one `IntersectionObserver` (a screen and a half of margin) and loads on demand; a scene switch prefetches its own cards instead of waiting for the next frame. On the current install boot drops from 15 scripts / 14 stylesheets to 10 / 8, and a scene switch brings the rest in with no empty bodies. The old light/heavy split and its 500 ms delay are gone.
- **One `MutationObserver` and one timer for every loading card.** `cfWatchForFirstPaint` created an observer and an 8 s failsafe per card, so a thousand extensions loading at once left a thousand observers and a thousand timers alive until each one painted. There is now a single shared observer (`cfPaintWatch` / `cfPaintOnMutations` / `cfPaintRelease`) and a single sweep armed at the earliest deadline.
- **`feather.replace()` is coalesced.** It scans the whole document for `[data-feather]` and was called once per card while the sidebar and grid were built - O(n²) document scans. `cfFeatherReplace()` collapses every request made in the same task into one pass.
- **Entrance animations are budgeted.** Only the first 48 cards of a grid build animate (`CF_APPEAR_MAX_ANIMATED`); past that the card is off screen while its entrance plays, so the class, the stagger and the 900 ms failsafe timer were pure cost. Cards that arrive later (a late extension) still animate.
- **Off-screen cards freeze their CSS animations.** `content-visibility: auto` already skipped their paint, but their animation clock kept ticking. `cfIdleObserver` adds `.cf-idle` to cards outside a one-screen margin, and `animation-play-state: paused` stops that work; removing the class resumes from the same frame, so nothing jumps. Never applied to a visible card.
- **The extension health poll backs off to 5 s.** `pollExtensionUpdates` ran at 1 Hz forever and returns one entry per extension, which is the heaviest idle cost at a thousand extensions. It is now self-scheduling: 1 s while anything is loading, a placeholder is up or the registry is empty, 5 s once the dashboard has settled (`cfHealthSchedule` in `core.js`).
- **Images decode off the main thread.** Core-drawn `<img>` icons carry `loading="lazy" decoding="async"`; images an extension paints get `decoding="async"` only, because `loading="lazy"` on an image an extension draws into a canvas can leave it permanently blank.

### Fixes

- **Sleeping with the laptop degraded every extension and quarantined it for the session.** The health monitor measures with `time.monotonic()`, which keeps counting while the machine is suspended, and `MAX_HEARTBEAT_AGE` is 60 s: the first tick after a resume saw every heartbeat hours old, marked all twenty degraded, restarted them on a still-warming machine, and quarantined for good any extension that had already spent its three restarts. The log is unambiguous - no activity between 09:28 and 10:03 on 2026-11-10, then 25 lines at 10:03 and 23 at 10:26, every one `heartbeat timeout` or `quarantined` - and `/api/extensions/health` then reported 15 dead out of 20 while those same extensions answered their methods in milliseconds. A long tick is now read as a suspend (`SUSPEND_GAP`, 30 s): heartbeats are re-stamped and the restart backoff is shifted by the gap, so waking up does not restart anything. Quarantine also became revocable - a heartbeat from a quarantined extension clears the flag and the restart budget, because a process that is still talking never died. Verified by suspending the real process for 96 s: `monitor tick gap 96s (suspend/resume), 20 heartbeats re-stamped`, zero timeouts, zero quarantines.
- **`process_manager` could never render.** `bridge.call` gave `get_processes` a 4 s budget while the extension needs 6-12 s to walk the process table, so every visible poll returned `Timeout: get_processes no responde (4.0s) - widget en degradado`. It now gets 20 s and returns its 44 KB payload in 6.2-7.6 s. Budgets are also readable from the manifest (`"timeouts": {"method": seconds}`), so the next slow method is declared by its extension instead of guessed in core.
- **The Reload button spun for the whole restart, and looked dead.** The click awaited `POST /api/restart` before calling `location.reload()`, and that handler drained every child synchronously: measured on 2026-11-09, 5.8 s from trigger to response, with a 10 s join deadline and a 5 s reap on top when one child refuses to die. Nothing was broken - the page always reloaded once the answer arrived - but the spinner outlasted the user's patience and the button read as stuck. The endpoint now answers **202 at once** and runs the reload on a daemon thread (`_restart_worker`, which also owns the lock release), the frontend caps the call at 3 s and reloads 300 ms later, and the registry is cleared **before** the drain instead of after it, so a page that comes up mid-restart sees the pending manifests and paints skeletons rather than cards whose processes are already dying. Verified from source: click to navigation in 0.5 s, 202 logged in the same millisecond as the trigger, and the grid back with `hot: 12` once the reload finished.
- **A visible widget could sit on `--` forever.** `cfPollRebuild` created the poller's `IntersectionObserver` and `cfPollRegisterAll` immediately disconnected it through `cfPollReset`, which kept the dead reference cached. Every later `observe()` therefore went into an observer that never delivered an entry, so no card was ever marked `hot` and `cfPollGate` refused every fetch: measured on the live window, `hot: 0` for twenty cards including seven in plain view, `lastAgo: null` on all of them, and `system_monitor` / `network_monitor` stuck on `--` and `Loading...`. Forcing `unobserve` + `observe` on one card turned `hot` 0 → 4 and the values appeared on the spot. Visibility no longer depends on the observer: `cfPollVisible()` reads the card's rect (one layout for the whole batch), `cfPollObserve` applies it immediately, `cfPollInvalidateScene` re-settles it after a scene switch, and a debounced `cfPollRecheck` does it on resize and on `visibilitychange`. `cfPollReset` now drops the reference so the next caller builds a fresh observer.
- **Off-screen cards could stay frozen forever for the same reason.** `cfIdleObserve` now applies `.cf-idle` from the card's rect instead of waiting for an entry that may never arrive, and `cfPollRecheck` re-settles every card on resize.
- **The bridge no longer spins while it waits for a child.** `_call` re-checked its response buffer every 10 ms, so every action paid up to 10 ms of dead time and the host kept a 100 Hz loop per in-flight call. Responses now arrive through a `Condition` the reader thread notifies. Measured on the i5-8250U: `/api/token` 6.5 ms, an inline child call (`get_status`) 8.3 ms, so the bridge itself costs about 2 ms instead of ~12.
- **`/api/quit` now uses the shutdown callback** the host registers, instead of signalling the process and leaving the window to be torn down abruptly.
- **The core is fully English:** splash status lines, tray menu, permission level labels and descriptions, escalation labels, toast and level-fallback text.
- **The child pipes are UTF-8 on both ends.** The child wrote the ANSI codepage and the parent decoded UTF-8, so every non-ASCII character in a widget value arrived as `U+FFFD` — `100% � 3200 DPI`, `MSD-ONE � Main` — with nothing logged. No extension was involved (pitfall 42).
- **A `text` widget no longer drops a structured value.** An object without `label` collapsed to `--`, which is indistinguishable from a timeout, so an extension that had answered looked dead. It now renders its fields as key/value rows, capped and escaped (pitfall 43).
- **The disabled flag survives a registry rebuild.** A disabled extension came back enabled every time the registry was written from memory.
- **`disabled` now lives outside the generated registry.** On 2026-10-22 an unreadable `extensions.json` was healed from the manifests and four extensions disabled since 2026-10-15 (`audio_recorder`, `msd_deck`, `overlay_windows`, `spotify_player`) started by themselves. The flag moved to `extensions.state.json` (`coreframe/extensions/state.py`), every registry write is atomic and keeps a `.bak`, a corrupt registry is no longer treated as empty when overwriting, and `extensions.json` only mirrors the flag. Verified by deleting the registry and booting: the healed file came back with the five flags intact.
- **An installed extension can no longer be invisible.** A directory with `extension.json` but no `main.py` (the Node demo) was skipped by the scanner, so it was neither loaded nor failed and never appeared in the Extensions panel. `/api/extensions` now lists it with a `loadError` and the panel shows its Delete button.
- **A version switch of an older build no longer undoes itself.** Downgrading `metadata_stripper` to 1.0 reported "installing", then the manifest still said 1.1. The published 1.0 carries no `permissions` field, so the loader parked it as legacy and returned `False`; the marketplace path read that as a broken build and rolled the files back, with `loadError` empty, so the only trace was `Install of ... failed: Unknown error`. A pending migration or a level bump is now a **prompt**, not a failure: the new files stay, the version is recorded and the UI opens the migration/consent modal. The zip wrapper folder is also taken from the directory holding `extension.json` and stripped only when every entry lives under it - it used to be "the first path segment of the first slashed entry", which read a flat archive's `formats/__init__.py` as a wrapper and flattened `formats/*.py` into the extension root on a fresh 1.1 install. Archive entries with `..` or an absolute path are rejected.
- **The Extensions panel describes the app as it is now.** It rendered the `/api/extensions` snapshot taken at boot, so an extension that finished loading later was missing until a full reload; it now fetches on open and prints `N installed · N active · N disabled · N with errors`.

## v1.1.0 — Permission System, Subprocess Isolation & Autoruns

**Release date:** 2026-09-01 — Security overhaul, long-term stable version for testing.

### Features — Permissions & Isolation

- **6-level permission model** (`basic 0` → `admin 5`) with consent modals, `permissions.json` + `permissions_denied.json`, and `file_whitelists.json` for `user_files` mediated access.
- **Subprocess isolation for all Python extensions** via `coreframe/extensions/ext_runner.py` (embebido como string en `run_coreframe.pyw`, sin archivos en `MEIPASS`) → `CoreFrame.exe --ext-runner <config.json>` JSON-RPC over stdin/stdout. Enforces `builtins.open` (allowed_dirs + exe dir + `_MEIPASS` + `TEMP` + `ext_path`), `socket` and `subprocess` blocking at OS level. Fixes `builtins.open` bypass via `import` time capture.
- **UAC elevation via `coreframe_helper.exe`** (`ShellExecuteW("runas")` + batch mode) for `registry_write`/`service_control`/`delete_file` — single UAC prompt, no need to run CoreFrame as admin. `win_tweaker` and `windows_autoruns` use it.
- **Escalation `Once` vs `Always`** — `Once` stored in `temp_escalations` and consumed after one successful `check_escalation`, `Always` in `permanent_escalations`. Frontend `permissions.js` shows `Once`/`Always` and `script.js` polls `GET /permissions` (100ms + socket) for instant retry.

### Features — Autoruns Extension

- **New extension `windows_autoruns`** (`system` + escalation `admin` for `toggle`) — native Autoruns clone: Registry `Run`/`RunOnce` (HKLM/HKCU/WOW6432), Startup folders, Winlogon, Services (125 via `SYSTEM\CurrentControlSet\Services`), Drivers, Scheduled Tasks (CSV), BHOs. Shows `Hide Microsoft`/`Hide Windows` (like Sysinternals), publisher via `GetFileVersionInfoW`, 16×16 icons via `SHGetFileInfoW→DrawIconEx→GetDIBits→PIL→base64` (114/167), table with `Disable`/`Enable` staying visible (grey `ar-disabled`, `disabled.json` for registry). SunshineService correctly appears as `AUTO_START` and toggles via helper `service_control`.

### Bug Fixes — Widgets & Scenes

- **Revoke paperweight:** `03-menus-styles.js` `showRevokeConfirm` now does `hideWidget` + `loadState().applyHiddenState` so revoked stays in `Extensions` and `Show hidden widgets` picker, only hidden from viewport.
- **Widget disappearance on scene switch/reload:** `02-layout.js` `saveAllLayouts` now only updates `col/row/w/h` for visible DOM widgets, keeps `hidden` from `widget_state.json` (source of truth). `01-scenes.js` `switchScene` simplified to 6 lines (no `deferred` magic, no `reload`).
- **Plain text fallback:** `switchScene` lazy-load now correctly does `loadExtAssets` + filtered `renderWidgets` for deferred, and `01-scenes.js` re-renders with `renderWidgets(filtered)` to avoid `--` → `text` plain.
- **Text selection in Autoruns table:** `style.css` `user-select: text` for `td`.

### Bug Fixes — Core & Security

- **Stale `widget_state.json` on scene change:** `saveAllLayouts` no longer reconstructs `hidden` from DOM, prevents empty `widgets: {}` on new scenes.
- **`ext_runner`  `TypeError: unhashable type: dict`** (f-string `{{e}}` in raw string) → fixed to `{e}`; `OSError Invalid argument` on close (stdout pipe) → `try/except OSError` around `ready` signal and `for line in sys.stdin`.
- **`PermissionError` on `MEIPASS` files:** `ext_runner` moved from `datas` file to `PYZ` hiddenimport + `exec(compile(...))` to avoid `Permission denied: _MEI.../ext_runner.py`.
- **`Security: cannot access .../CoreFrame.exe`:** `allowed_dirs=['/']` only matched `C:\` on Windows; added implicit allow for `sys.executable` dir + `_MEIPASS` and handling for `'/'` as any absolute path; added `DATA_DIR` handling for `user_files`.
- **Double wrap `{"value":{"value":...}}`:** `bridge.py:_call` now returns `result` directly if dict, fixes `notes`/`fortune_cookie` `[object Object]`.
- **CMD flash every 2s:** `bridge.py` `CREATE_NO_WINDOW|DETACHED_PROCESS` + `STARTUPINFO SW_HIDE` + `ext_runner` child `Popen` patch for `CREATE_NO_WINDOW`.
- **Slow startup (2.5s):** `health.py` `max_workers 8→16`, `bridge` `sleep 0.1→0.01`, `loader` prioritizes visible (but now loads all, ~0.5s for 3 visible).
- **Slow scene switches with heavy widgets (e.g. image_gallery):** root causes were per-switch image revalidation (`Cache-Control: no-cache` on `/ext-static`) and full render cost of off-screen cards. Core now serves immutable extension media (thumbs + images with content-stable names) with `public, max-age=86400` so repeat switches cost zero requests, scene backgrounds likewise; widget cards get `content-visibility: auto` so hidden/off-screen widgets skip layout/paint. Switch path itself verified non-blocking (no awaits, async fills, threaded server). Extension untouched.
- **Scene-switch immunity guarantee:** `switchScene` commits synchronously with zero network, zero awaits and zero extension invocation — a hanging or endlessly-loading widget can never hold a switch hostage; its content fills in afterwards at its own pace. Rapid toggles coalesce via generation counter (N fast toggles = 1 apply pass + 1 persist POST), `saveAllLayouts(skipPersist)` decouples position-saving from persisting, and the commit self-reports via `console.warn` if it ever exceeds the 50ms budget.
- **Staged reveal:** visible widgets unhide in batches of 4 per animation frame (`s._revealPerFrame`) with generation guard - a heavy widget only ever delays its own paint, never the switch commit, other widgets or input. Non-scene widgets hide first in the same frame (cheap, no content cost).
- **Visibility-gated refresh (measured: `process_manager/get_processes` takes 3.2s backend on a 3s interval):** `refreshWidget` skips widgets hidden in the active scene and skips while a previous call for the same widget is still in flight (anti pile-up); realtime socket updates skip `display:none` cards; `addExtensionToUI` no longer double-drives `js_modules` widgets; `unhideWidget` and post-reveal refresh visible core-driven widgets once so shown content is fresh. Hidden widgets now cost zero backend calls and zero DOM work.
- **Instant loading screen:** PyInstaller bootloader `Splash` (`splash.png`, same theme as GDI splash) paints at ~T0+0.2s covering the ~3.5s MEIPASS extraction; `pyi_splash.close()` hands off to the animated GDI splash (killed immediately in `--ext-runner` children — verified zero TkTopLevel flashes after handoff via window enumeration). `import clr` (.NET init) deferred until after splash paints; Flask server thread starts in parallel with `import webview` instead of serially. Measured: pixels 3.5s→0.2s, total boot ~6.3s (extraction+AV bound, varies 3–8s per AV cache).
- **Single small loading screen:** removed the GDI animated splash — now only the bootloader splash (440×330, centered) shows, with live status lines via `pyi_splash.update_text()` (`Iniciando interfaz...`, `Cargando aplicación...`, `Cargando vista...`, `Abriendo ventana...`) for loading feel. Closes exactly once at window reveal (watchdog/error/autostart paths included); `--ext-runner` children and second-instance exits close it immediately. Verified: Tk 440×330 centered from +0.2s, no `CoreFrameSplashCls` window ever created, closed at reveal.
- **Autostart mode that actually works:** new system-tray icon (hidden mode only) with tooltip stating the mode (`inicio automático activo` / `minimizado`), balloon on start, double-click to open, menu with Abrir + graceful Salir (via `/api/quit`, stops server + extensions). Fixed tray breaking `webview.start` (`InvalidOperationException`: WinForms objects must not be created on the main thread before pywebview setup — tray now lives on its own STA thread with its own loop). Fixed watchdog popping the window visible in hidden mode. Bootloader splash no longer always-on-top. Server wait retries 3×30s in hidden mode with silent fail (no popup over the login screen); extension ready timeout 15s→30s for HDD/login-storm boots (E: is spinning disk).
- **Scene `widget_state` loss on `createScene`:** fixed `persistScenes` atomic write.
- **Autostart toggle indicator:** the Start on boot menu item now shows a green ON / grey OFF badge plus check/square icon. Fixed two bugs hiding it: `feather.replace()` was never re-run after the async state fetch (raw `<i>` stayed invisible), and `_get_autostart_enabled` ran `isfile()` on the whole registry string including quotes and args (`"...\exe" --autostart` always False), so it reported OFF even when enabled.
