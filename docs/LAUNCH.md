# Launch readiness

State of the project as of 2026-11-25, and what is left before calling it released. Keep this
file honest: it is the checklist a stranger would run before trusting a download.

## Green

| Check | Evidence |
|---|---|
| Tests | `python -m pytest -q tests` → 29 passed in ~3 s. CI runs it on Windows and Linux before the build |
| CI | `.github/workflows/build.yml`: version sync → tests → license texts → runner mirror → build → tag-gated release |
| Version | One command (`tools/bump_version.py`) writes `config.py`, `version_info.txt`, `runner_version_info.txt`; CI fails when they disagree |
| Marketplace | <https://coreframe-marketplace.roftcore.work> live, HTTPS, 12 extensions, 15 releases |
| Release integrity | `sha256` + `size` per release in the registry, generated by `tools/hash_registry.py --write`, checked in CI, **verified by CoreFrame before installing** |
| License compliance | `LICENSE.md`, `NOTICE`, `AUTHORS`, `THIRD_PARTY_NOTICES.md` and 57 files under `licenses/` packed into the exe |
| Governance | GPL-3.0-or-later from v1.1.0, `AUTHORS`, CLA in `CONTRIBUTING.md` |

## Before the next public release

1. **Bump the version** - `python tools/bump_version.py`, then commit. Any change to the built host needs it.
2. **Run the suite** - `python -m pytest -q tests`.
3. **Merge `development` into `main`** and tag `vX.Y.Z`. CI builds Windows and Linux and publishes the release with the CHANGELOG section as its body.
4. **Update the marketplace** if the release changes anything an extension depends on: `tools/hash_registry.py --write` after republishing an asset, then push (CI re-checks).
5. **Attest the download**: the release asset is built by CI from the tag, and the version in the exe (`FileVersion`) must match the tag.

## Known issues that do not block a release

- **Crash on close** (`c0000005 in python311.dll`, since September, three builds). No traceback; the measured candidate is the machine-wide `PYTHONPATH` pointing at 3.11 site-packages, imported by a frozen 3.13 process. Reproducing it needs the machine that crashes. Documented in `AGENTS.md`.
- **No in-app update notice.** The version is visible in Settings → footer, and releases are public, but nothing tells a user that a newer one exists. Planned: registry carries an `app` block, Settings links to it.
- **Three dependencies ship no license text** (dnspython ISC, GPUtil MIT, proxy-tools MIT). `licenses/INDEX.md` lists them; the text has to be fetched from the package source.
- **`script_scope` migration**: 2 of 13 installed extensions declare `"module"`. The rest still share the global scope (pitfall 60). New extensions must declare it.
- **Windows is the only runtime anyone has exercised.** Linux builds, but nobody has run it end to end.

## What "released" means here

A tag whose assets a stranger can download, install, open the Marketplace, install an extension whose
hash matches, and find the license and the notices inside the binary. Everything in the table above is
what makes that sentence true; the list below it is what makes it not yet perfect.
